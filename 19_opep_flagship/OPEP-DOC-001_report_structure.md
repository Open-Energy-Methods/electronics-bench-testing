# Flagship portfolio — engineering dossier and learning evidence

Create a durable **engineering design dossier**, not a skills shopping list.
Each module has a short technical report, real photographs if permitted,
editable native design, reviewed drawings, calculations and validation
evidence. Group the main report by engineering lifecycle:

1. User needs, system definition, feasibility, standards and alternatives.
2. Requirements, interfaces, design reviews and risk management.
3. Mechanical design, FEA and tolerance/fixture engineering.
4. Production: CAD/CAM, machining, printing, cutting, process planning,
   workholding, first-article inspection and cost/productivity.
5. Electrical/electronic design: schematic, PCB if justified, verified
   component selection, signal conditioning, electrical safety.
6. Sensors, oscilloscope, dimensional measurement, calibration and uncertainty.
7. Thermal/fluids and environmental equipment, CFD and validated boundaries.
8. Controls, automation, data integrity, dashboards and digital thread.
9. Commissioning, verification, observed deviations, root causes and changes.
10. Scientific studies and portfolio summary; separately identify EBT Q0/R01.

Competence levels: observed, trained, supervised exercise, approved
task-specific operation, demonstrated repeatable result. Only record levels
with actual evidence; do not imply formal certification. Dates, versions,
instrument identity, actual measurements, feedback and limitations matter.
Do not use stock imagery as personal evidence. Each physical result has its
own independent artifact ID. Public GitHub contains redacted permissible
records; real approvals, personal IDs and restricted certificates stay private.

## Closed-loop additions
For each module, add an intended-use statement, pre-test blind prediction,
solver/mesh/time-step verification, as-built model, measurement uncertainty,
CAL/VALIDATION partition, comparison and discrepancy assessment, change
request if needed, new independent validation and bounded model release.
Document experimental modal analysis, FRFs, coherence, damping and mounting;
calibrated acoustic pressure, room background and transfer functions; CFD,
FEA and COMSOL model settings if licensed/access permitted; reduced-order
models; synchronized measurement replay; external ThermoTwin-F interface and
limits. Record failed comparisons, not only aligned plots. Distinguish design
model, offline validated model, one-way operational shadow and live twin.
Include source and permitted native solver projects, hashes, mesh data,
postprocessing, environment versions, and independent reproduction notes.

## Career-facing evidence packages (004)
Write one two-page technical work sample per accepted campaign and link to
native files, test data, independently validated prediction, uncertainty and
actual change records. Include as-built inspection, PFMEA/DFMEA, control plan,
DVP&R, nonconformance, calibration, method and sign-off limitations as relevant.
Use public job-derived competencies, not copies of private applications or
unverified skills claims. Separate a completed engineering artifact from
industrial qualifications or nuclear-code compliance. Study codes legally and
record intended-use applicability rather than claiming certification.
